# Frontend implementation scope

## Contract

**Approved v1.3 / D-51 presentation; retained D-47 business layouts/login.** This document narrows design context for implementation; it does not add tasks, routes, application roles or backend scope. Preserve the existing 230 tasks / 88 packages and Phase A → B → C → D order. FE-18.03 still gates later phases.

## Shared presentation

Apply [approved Mac/Teal](approved-format.md) and [mac.css](final/mac.css) after the shared source styles. Static AI canvases are references only; implement responsive components and task-owned acceptance. Login remains unchanged.

Use [tokens and components](design-system.md): Light purple surfaces, dark readable text, semantic luminous KPI edges, the approved four-font hierarchy and restrained spacing. Retain the selected purple navigation/header and one AI Workspace entry. Mobile must reflow at 320/390/768/1440 and remain usable at 200% zoom. Decorative glow must not replace readable glyphs, labels or focus.

## Login contract

**Sole implementation owner: FE-03.01.** Port [login.html](final/login.html), [login.css](final/login.css), [login-background.svg](final/login-background.svg) and [scene behavior](final/login-scene.js) into maintainable application components. Preserve the local asset; do not add an image-generation, 3D engine or external-data dependency.

- Solid navy canvas, layered architectural floor/shadows and restrained slate glass. Desktop outer card 460px / inner content about 370px, centered title, persistent labels, 50px inputs, 48px yellow action. Responsive widths/padding reflow; mobile inputs are at least 16px text.
- Eye target is 44×44px inside the password field; reserve 56px right padding. Hover/press stays transparent, icon may brighten, keyboard focus stays visible. Show/hide preserves value, selection and target geometry; no clipping, overlap or shifting in either state.
- Ten circuit tracks total, brighter thin strokes and staggered moving packets. IT Support / meeting / infrastructure regions brighten on hover, keyboard focus or selection; click selects/deselects with `aria-pressed` and a concise text alternative.
- Bounded background parallax (48px/32px full pointer span), localized region zoom, pointer light and transient background-click ripples. Form and buttons do not move. Touch does not require hover or drag.
- A single pause control stops every track/packet, parallax, ripple and ongoing decorative animation. Honor `prefers-reduced-motion`; cancel pending frames/listeners on unmount. No animation gates validation or login results. Mobile exploration buttons flow below the form and do not cover its controls.
- Keep the mock login/validation/loading/error contract. Demo account selection is separate from product UI; no signup, SSO or self-service reset is added. Help directs the user to Admin. Do not copy the specimen's demonstration-only success dialog in place of the planned mock session flow.

FE-02.01 supplies reusable tokens/inputs/buttons, not a second login scene. FE-03.02 owns session entry/return routing; it consumes FE-03.01. FE-18.02 verifies the final login and every-motion pause/reduced-motion behavior; FE-18.03 records final design conformance at Phase A handoff.

## Domain screens and AI

Use only the affected group/role and its task's US/AC/BR/API/SCR sources. Tickets, work, workforce, assets, knowledge, administration and reports retain their existing business scope. Chart styling includes blue created / striped teal resolved, values/dates/legend, keyboard details and a table fallback. Keep manual actions available under existing permissions.

AI references preserve chat/activity/context/action placement; apply the v1.3 Mac/Teal styling rather than the retained SVG dark palette; build semantic responsive components and real planned interactions. A static SVG scroll canvas is not mobile AI acceptance. Background coordination, approval, models/RAG and database work remain owned by the existing FE/service/integration tasks. No static design animation proves a business event happened.

## Acceptance boundary

For each task, compare only its owned implemented surface to the named source, record the actual viewport/state/keyboard/reduced-motion results in its existing Evidence and handoff and task-history format, and link the latest report from current-context. No task may claim all-screen conformance from a single screenshot. Scaffold/transport-only tasks respect the baseline but do not build feature screens early. INT tasks preserve approved presentation while wiring services; QA tasks assess affected implemented journeys without adding feature ownership.

The supplementary spatial view is not a mandatory new app module. Design catalog navigation, review tools, capture flags and browser-test harness are documentation-only and must not become product UI. No further visual alternatives are in scope without an owner-approved change.

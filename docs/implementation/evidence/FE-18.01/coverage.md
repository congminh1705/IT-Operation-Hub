The four-role [coverage spec](../../../../src/frontend/e2e/phase-a-coverage.spec.ts) enters the normal login and clicks each role’s 50 combined sidebar destinations. It checks for native content, no pending shell and no empty action link. Modal and mutation outcomes are exercised by the named suites. Account menu items use the [A1 journey](../../../../src/frontend/e2e/a1-handoff.spec.ts), including logout and switching. In addition, coordination policy/version, activity fallback, exception execution, attachment retry/download, task lock, SLA forecast and report parity are covered in the functional browser suite.

## Route and specimen notes

- IA route patterns are proposed navigation designs. Asset metadata and team membership are reached through their native catalog controls. Asset, plan and audit details use application query state where applicable. These are included in the inventory without adding parallel routes.
- SCR90 and SCR91 are runtime feedback on denied, missing or out-of-scope destinations. The generic state specimen maps to shared feedback and feature-local failures. /preview routes are QA fixtures and excluded from role sidebars.
- The opening Chrome pass found an outdated FE-05.02 assertion after FE-12.04 expanded the eligible device fixture. The test now verifies both named eligible devices and the optional no-link choice. No product behavior was changed.
- The catalog is a review tool. Dashboard application/reference pairs are documented in [comparison.md](comparison.md). Existing task-owned reference evidence remains linked by its original card.
